# 子智能体派发与回收

子智能体是实际派发的工作线程。把一段回答标成多个角色不等于创建团队。短任务和有紧密依赖的步骤由当前智能体直接处理；适合拆分的是可独立获取的证据、互不重叠的实施范围，或需要独立判断的复核。

## 一次约定后的按需委派

- 用户已一次约定委派边界后，本框架要求当前主智能体在独立工作或独立复核能改善结果时，按需使用实际可用的子智能体工具派发；原任务授权内的检索、实施和职责内自检均可委派，不逐次确认岗位或人数。
- 当前主智能体负责派发、回收和汇总；需要单独设置主控岗位时由用户指定。成员可在既有任务授权内实施，委派不扩大外部操作或运行权限。
- 仅选择工程、科研、汇报场景或成长、穷举、爆破模式，不构成启动子智能体的指令。
- 数量按独立任务与运行时可用槽位决定，不预设每个功能一个成员。成员只具备当前工具与权限；没有派发能力时直接说明，由单智能体完成可承担的工作。

Codex 支持由用户请求或适用的 `AGENTS.md`／Skill 指令触发派发。子智能体各自执行模型与工具工作，会增加总体用量；并行收益取决于任务能否独立推进。[OpenAI 子智能体说明](https://learn.chatgpt.com/docs/agent-configuration/subagents)

## 派发内容

每个任务给出足够执行的边界，通常一段话即可：

- **目标与交付物：** 要回答的问题、修改结果和完成标准。
- **输入与上下文：** 原始资料路径、相关用户决定、已有证据；独立复核避免灌入预期答案。
- **职责与写入范围：** 允许操作的文件或目录、与其他成员的依赖、需要调用的 Skill 实际路径。
- **回报要求：** 结果、依据、实际检查、未完成项，以及会影响汇总的分歧。

模型默认继承；思考强度按 [high／max 规则](reasoning.md) 明确指定：同一批同类任务一名执行者用 `max`，多名并行执行者各用 `high`，不同类任务分别计算。上下文继承方式以工具实际支持为准：续接已有工作可继承历史；独立核查可仅提供原始资料和问题。省略历史时必须补齐任务约束、用户选择和必要输入；共享文件不代表共享对话或记忆。

## 跟进与收敛

1. **派发后推进独立工作。** 只拆可独立推进的任务，耦合紧的步骤按依赖串行；成员承担职责内自检，需要独立判断时再复核，不重复整套检查。
2. **协调共享写入。** 实施前明确共享接口；同一文件由一名成员负责写入，其他成员返回建议。共同工作区内保留他人的改动，主线程统一集成和处理冲突，并统一完成提交、推送与同步。写入范围是工作约束，不把它说成系统级隔离。
3. **及时传递纠正。** 用户改变目标、范围或取消任务时，向受影响成员传递新约束；不再需要的工作使用当前工具提供的中断或停止能力处理。下级继续派发也必须有适用的派发指令和可用容量。
4. **回收实际结果。** 依赖成员结果的步骤等待其回报；按工具的等待语义使用合理间隔，避免密集轮询。失败、超时或不完整结果保持未完成状态，不以主控猜测补成成员结论。
5. **汇总有依据的成果。** 按任务完成标准检查产物与关键证据；有分歧时对照原始资料，说明剩余未知，不按人数投票决定事实。记忆与 Skill 候选纳入阶段末确认清单。只有任务已完成、已交接或已停止时才汇总相应状态；已完成成员可复用或按工具能力关闭。

向用户说明谁实际承担了什么、得到什么，以及真正需要决定的取舍。成员回报不是自动批准，复核成员也不因身份而有更高事实可信度。

## 本地自定义成员

只有同一种分工需要反复复用时，才考虑自定义成员。当前 Codex 支持在 Codex 主目录的 `agents/` 或项目 `.codex/agents/` 中定义 TOML 文件，必需字段为 `name`、`description` 和 `developer_instructions`；模型与思考强度可以另行配置。共享规则与可复用工作方法仍放在 `AGENTS.md` 和 Skill 中。具体格式和支持情况按当前客户端核对。[OpenAI 自定义子智能体说明](https://learn.chatgpt.com/docs/agent-configuration/subagents#custom-agents)

部署本 Skill 仅安装派发规则，不会创建成员线程或安装自定义成员配置。
