# 子智能体派发与思考强度

先判断分工能否改善结果，再决定成员与强度。当前智能体能直接完成的小任务直接推进；独立取证、并行实施或独立判断有价值时，使用实际可用的子智能体工具。

## 按需委派

用户已一次约定委派边界后，可委派原任务授权内的检索、实施和自检，不逐次确认岗位或人数。当前主智能体负责派发、回收和汇总；集成与交付指定一名责任成员，可交由子智能体承担。另设专门主控岗位时由用户指定。

根据任务收益、依赖与运行时容量决定分工。耦合任务可先约定接口，再并行推进独立部分，按依赖集成；成员承担职责内自检，需要独立判断时再安排复核。委派范围沿用原任务授权。

## 派发时设置强度

| 同一批同类任务的执行者 | 思考强度 |
| --- | --- |
| 同一时段一名，包括串行分工 | `max` |
| 多名并行执行 | 各用 `high` |

同类按工作功能判断，不同类分别计算；当前主智能体若参与同类专业工作，也计入人数，只负责协调则不计入。先决定必要分工，再按人数设置强度，不为调整强度增员。

调研检索同样按人数计算：一人检索用 `max`，多人并行检索各用 `high`；一人检索、一人实施属于不同类任务，各用 `max`。批次开始或派发前确定参数，后续批次按届时分工重算。

每次派发通常一段话即可，给出目标、交付物与完成标准、必要资料和用户决定、操作范围与依赖、模型及强度、回报要求。模型沿用用户选择；回报包含结果、依据、实际检查和未完成项，并说明检查对象与可识别版本：已有提交用提交号，未提交时注明所检文件状态或具体内容。独立复核优先提供原始资料和问题；省略历史时补齐必要约束与上下文。

## 协作与回收

- **协调写入。** 共享工作区约定修改范围，避免相互覆盖，保留他人改动。隔离工作树或其他实际隔离的工作区可并行修改同一文件，由责任成员集成并处理冲突；按原任务授权完成提交、推送和同步。
- **传递变化。** 用户调整目标或范围时通知受影响成员和依赖其结果的成员；取消的工作使用实际可用的中断或停止能力处理。停止成员不等于撤销已发生的修改或外部动作，交由责任成员核对处理，不自动删除。下级委派仍需适用的派发指令与可用容量。
- **回收证据。** 依赖成员结果时按工具语义等待，期间推进其他独立工作。有分歧则对照原始依据；失败或不完整结果保留未完成状态，不以人数决定事实。
- **形成交付。** 按完成标准检查成果，核对关键证据仍适用于集成后的版本。复核后又有改动或合并改变了检查对象时，只重做受影响的检查；不把旧版本的通过结论记作新版本已验证。向用户说明实际分工、结果和需要决定的取舍。记忆与 Skill 候选集中到阶段末确认；成员回报不增加操作权限。

## 按需查阅：运行兼容与自定义成员

默认使用运行时已有派发工具，角色和边界随任务提供。反复复用同一种分工时，再考虑 Codex 支持的自定义成员配置；共享规则与方法继续放在 `AGENTS.md` 和 Skill。[OpenAI 子智能体说明](https://learn.chatgpt.com/docs/agent-configuration/subagents)

- **参数与上下文。** 在支持的调用中明确设置强度，核对工具限制。例如当前 `collaboration.spawn_agent` 的全历史继承（省略 `fork_turns` 或设为 `"all"`）不能同时覆写强度；需要覆写时选择工具支持的有限历史或无历史，并补齐执行所需信息。
- **实际生效。** 自定义成员或配置默认值可能影响最终参数，按客户端实际优先级核对。区分请求值、配置值与能观察到的运行值；无法核实时说明限制，规则文字不代表本轮参数已经改变。
- **运行中调整。** 已启动调用能否修改强度取决于工具能力；无法调整时在下一次可设置的调用应用规则，不擅自修改全局模型配置。
