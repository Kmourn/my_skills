# 子智能体派发与思考强度

## 按收益拆分

能直接完成的小任务由当前智能体推进。独立取证能补足依据、独立复核能改善判断，或并行实施能缩短关键路径时，按工作依赖和可用容量委派。耦合工作先约定接口和集成顺序，成员各自检查职责内的成果。

用户已约定委派边界后，主智能体在原任务授权和用户约束内决定分工与人数，负责派发、回收与汇总，并指定一名成员负责集成和交付。需要单设主控时由用户指定。下级委派同样遵循适用的派发指令与容量限制。

派发时给出目标、基准版本或源材料、操作范围与依赖、交付物和验收标准，传达相关用户决定及约束。独立复核优先提供原始资料和待判断的问题。回报说明成果、依据、所检对象和版本、实际检查及未完成项。用提交号或未提交时的文件状态标识版本。

共享工作区约定各自的修改范围。需要并行修改同一文件时，使用隔离工作树等实际隔离的工作区，由集成责任成员解决冲突并保留已有改动。运行多个计算进程时，按可用资源、单任务占用和运行表现调整进程并发，与智能体人数分别决定。

## 设置思考强度

| 同一批同类任务的执行者 | 思考强度 |
| --- | --- |
| 同一时段一名，包括串行交接 | 使用所选模型和运行环境支持的最高档，优先 `ultra`，其次 `max` |
| 多名并行执行 | 默认各用 `high`，任务需要时可让部分或全部并行成员使用上述最高档 |

按工作功能分别计数，检索和实施等不同类任务各自计算。主智能体参与同类专业工作时计入，仅协调时不计入。先定分工再设参数，后续批次按实际分工重算。

沿用用户选定的模型及明确指定的强度。在可设置的调用中明确选择单一档位。设置参数影响历史继承时，补齐执行所需的上下文。核对请求值、配置优先级和可观察的生效值，无法设置或核实时说明限制。运行中的调用无法调档时，在下一次可设置的调用应用规则。

## 按依赖集成

优先回收影响交付的结果，等待期间继续独立工作。分歧对照原始依据处理，必要证据未齐时继续跟进，其余结果按实际状态记录。

收到反馈先定位涉及的交付物和版本。责任成员可直接修改职责内的部分，涉及其他工作或依赖时通知相关成员。取消工作时使用可用的停止能力，由责任成员核对已发生的修改和外部动作，按原任务授权处理。

集成后按验收标准核对成果及关键证据适用的版本，修改和合并只触发受影响部分的复查。按原任务授权完成提交、推送与同步，向用户交付成果，说明实际分工、检查结果和未决取舍。记忆与 Skill 候选集中到阶段末确认。
