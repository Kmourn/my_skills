# 个人记忆、任务续接与 Skill 沉淀

记忆优先保留用户已确认的个人偏好。可复用的方法由 AI 评估是否沉淀为 Skill，再交用户确认；通用推进经验优先更新 `steady-progress`。任务状态和项目事实继续保存在项目记录，避免与个人偏好混写。

## 保存位置与依据

| 内容 | 保存位置 | 写入条件 |
| --- | --- | --- |
| 当前任务的目标、进展、证据与下一步 | 项目已有记录；缺少时才建立一份任务记录 | 在任务授权内维护，沿用已有格式 |
| 项目事实、接口与已确认决策 | 项目文档或已有决策记录 | 有文件、提交、运行结果或用户决定作为来源 |
| 个人长期偏好 | 当前 Codex 主目录下的 `collaboration-memory.md`，或用户指定位置 | 阶段末呈现具体条目与范围，由用户确认后写入 |
| 可复用方法与通用协作规则 | 优先 `steady-progress`；专业方法归相应 Skill，必要的加载入口归 `codex/AGENTS.md` | AI 评估并呈现具体改动，由用户确认后按维护流程部署 |

Codex 主目录按非空 `CODEX_HOME`、否则 `~/.codex` 解析。`collaboration-memory.md` 是本框架约定的人工维护文件，只有指令明确要求读取时才加载；它不是 Codex 原生记忆文件。不为每个任务新建一套记忆目录。

## 读取与更新

1. **续接先定位。** 读取用户指定的进展文件和当前项目已有任务记录，再按需要查看相关证据。读取长期偏好时只选与当前任务有关的条目。
2. **区分状态。** 把用户已确认的决定、观察到的事实和仍待验证的判断写清楚。每项重要结论给出文件、提交、运行记录或用户消息的来源与日期；计划执行的检查不能写成已通过。
3. **阶段内维护任务记录。** 在有实质成果、重要纠正或需要交接时更新同一份项目记录。保留目标与范围、已确认选择、完成项及证据、未完成项和下一步；原始日志和产物用链接引用。偏好和 Skill 候选只标作待确认，不作为未来任务的已生效规则。
4. **处理冲突。** 当前用户指令和已核实的现状优先。核对记录与当前任务是否一致，不等于重复请求仍适用的授权；只对会改变下一步的缺项、冲突或范围变化提出问题。过期的项目事实就地修订；个人长期偏好的修订加入确认清单。过去的场景与模式只对记录中的任务和阶段有效，新会话的首次确认仍遵循当前适用的 `AGENTS.md`。
5. **阶段末统一确认。** 在大段工作结束、阶段成果形成或交接时，集中呈现拟保存的偏好、拟沉淀的方法、来源、拟写位置和具体影响。每次个人偏好新增或修订都由用户确认，不因 AI 判断明确而自动保存；已对具体条目确认后执行，不重复问同一清单。用户直接要求删除明确条目时按该指令执行，并说明是否涉及其他存储。

AI 自由评估内容的复用价值，不预设固定次数或格式门槛；优先扩展合适的已有 Skill。个人偏好和执行方法分别说明，候选可以一并交给用户选择。当前任务内的纠正先执行，不必等待长期沉淀确认。

需要建立任务记录时，可用以下最小骨架，并删掉无用项：

```markdown
# 任务续接
- 目标与范围：
- 已确认选择：场景、模式、必要分工及适用阶段
- 已完成与证据：文件／提交／检查结果
- 当前判断：事实／推断／待验证
- 未完成与阻碍：
- 下一步：
- 更新时间与来源：
```

项目记录可以记下已有授权的范围，续接时仍需核对当前任务和运行权限。历史授权不能自动扩展到新任务，撤销或收窄的授权以最新指令为准。子智能体回报先核对依据，再由负责汇总的智能体写入共享记录；避免多人同时维护同一份记录。

## Codex 原生记忆

原生记忆是可选的回忆层，必需规则仍放在 `AGENTS.md` 或项目文档中。原生记忆使用 Codex 主目录下的 `memories/`，由系统后台生成，不具备本框架逐批确认个人偏好的写入流程。因此已确认偏好由人工维护文件承载，原生自动生成需用户另行选择，不代替阶段确认。CLI 的 `/memories` 可控制当前聊天的读取与贡献行为。[OpenAI 官方记忆说明](https://learn.chatgpt.com/docs/customization/memories)

若选择只读取已有原生记忆、停止后续生成，在已有 `config.toml` 的相应表中合并以下项；不要直接追加重复表或覆盖其他配置：

```toml
[features]
memories = true

[memories]
use_memories = true
generate_memories = false
```

这是可选配置示例，部署本 Skill 不会自动修改这些开关。用户另行选择后台生成时才将 `generate_memories` 设为 `true`；停止读取将 `use_memories` 设为 `false`。这些开关不等于删除已有记忆；删除原生记忆使用客户端实际提供的管理方式，能力不足时说明限制。[OpenAI 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)

人工维护的个人偏好、原生记忆、会话日志与凭据留在本地，不随 Skill 框架上传 GitHub。项目记录进入版本控制前遵循项目已有的数据分享约定；本框架仓库仅保存规则和空模板。
