# 场景决定工作功能

以下是**可选工作功能**，不是固定岗位、人数或顺序。单智能体可承担全部必要功能；启用实际团队后，专业成员承担工作，用户指定的主控负责分工和汇总。先看当前任务的最近一项可交付成果，再选择必要功能；一名成员可承担多项，只有独立工作或独立判断能明显改善结果时才拆分。

## 工程

| 工作功能 | 交出的结果 | 何时值得分开 |
| --- | --- | --- |
| 需求与代码侦查 | 已有行为、接口、相关文件、约束和未明之处 | 仓库较大，侦查可与其他独立工作并行 |
| 技术设计 | 最小实施路径、接口与依赖、主要失败路径 | 跨组件或设计取舍会影响多个实施范围 |
| 实现与集成 | 最小可运行增量、实际改动及职责内自检 | 范围互不重叠且能清楚约定接口 |
| 验证与独立复核 | 实际证据、规格偏差、回归风险和待人工验证项 | 需要独立审查，或实现者容易漏掉关键边界 |

匹配 Skill 时优先看当前问题：复杂实施路径可考虑规划类，跨组件故障可考虑系统调试类，明确的独立审查可考虑代码审查类。**不要把这些类别固定到某个角色或阶段。**ROS 节点或实物运动测试优先人工执行；如需自动测试，先获得用户明确许可。场景本身不授权运行未获准的测试。

## 科研

科研按当前问题组合工作功能，不预设规划、执行、评估岗位。同一成员可以从检索做到实验和写作；当核心主张需要不受原思路影响的判断时，再安排独立复核。

| 工作功能 | 交出的结果 | 何时值得分开 |
| --- | --- | --- |
| 问题与证据探索 | 研究问题、文献与数据线索、最接近的工作和来源缺口 | 检索方向可独立开展，或查新需要复核 |
| 假说与方法 | 可区分的假说、替代解释、预测及判别性实验设计 | 多条研究路线需要并行比较 |
| 软件实验与数据分析 | 代码、运行记录、原始结果、分析图表和不确定性 | 可明确拆成独立实验，或数据处理需要核对 |
| 对抗复核与迭代 | 最强反例、混杂、证据链和创新有效性异议；补实验或修正建议 | 核心主张需要不受原解释影响的审查 |
| 论文／报告表达 | 与证据对应的结论、图表、引文和待核实处 | 多条研究线要合并，或稿件需要独立审读 |

完整科研任务可沿“问题与证据 → 假说 → 实验设计 → 获准的软件实验 → 分析与对抗复核 → 补实验／修正主张 → 论文或报告”推进；这是可回返的研究闭环，不是强制固定阶段。科研的对抗复核强度最高，但必须依据可核查材料，不为制造分歧而编造反例。按当前问题选用检索、实验设计、统计、绘图、写作或主张复核类 Skill；没有专门 Skill 的普通代码工作仍可直接完成。证据不足时标明条件结论；ROS 节点与实物运动测试优先人工执行，如需自动测试，先获得用户明确许可。

## 汇报

| 工作功能 | 交出的结果 | 何时值得分开 |
| --- | --- | --- |
| 来源核实 | 可追溯的事实、数字、图表和待确认项 | 来源多或事实错误代价较高 |
| 受众与叙事设计 | 受众需求、核心信息、顺序和信息层级 | 叙事取舍需要与制作分开讨论 |
| 内容与视觉制作 | 可编辑交付物、图文布局和呈现记录 | 内容、图形和版式工作可并行且有共同结构 |
| 成果核查 | 来源一致性、叙事连贯性、术语和视觉风格 | 需要独立检查观众理解或最终一致性 |

按用户已有偏好，未另指定时优先可编辑 PPTX，网页可作补充。汇报的对抗式评估较轻，侧重风格一致性；**事实核实仍是必要工作**，可由来源核实者或制作成员承担，不必硬塞给评估者。匹配 Skill 时看来源审查、演示文稿制作与视觉核查能力；不要因“汇报”标签自动加载全部。
