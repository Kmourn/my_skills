# Codex 通用协作约定

## 默认加载

每个新会话首次收到任务时，先读取以下已部署 Skill。优先使用当前可用 Skill 清单提供的 `SKILL.md` 路径；清单未提供路径时，在当前 Codex 主目录下的 `skills/<Skill 名称>/SKILL.md` 定位：

- 稳健推进（`steady-progress`）：统一维护任务推进约束、阶段末记忆与 Skill 确认、按需委派及 high／max 指派规则。
- 场景与模式协作（`scene-mode-collaboration`）：用于首次场景、模式确认及后续协作配置。

Codex 主目录优先使用非空的 `CODEX_HOME` 环境变量；未设置时使用当前用户主目录下的 `.codex`，即 `~/.codex`。先展开环境变量及 `~` 再读取文件，不按固定用户名拼接路径。若找不到所需 Skill，说明缺失并请用户提供部署位置。

## 首次确认与后续推进

1. 首次接到任务便询问用户选择场景（工程、科研、汇报）和模式（成长、穷举、爆破）。根据任务内容给出推荐组合及简短理由，也允许用户调整。用户已在任务中明确指定的项直接沿用，只询问尚未明确的项。
2. 等待用户确认后，再按 `scene-mode-collaboration` 提出分工、Skill 与人机交接建议。等待期间，可做不依赖场景或模式选择的必要查看与信息整理；不把推荐或用户沉默当成确认。
3. 同一会话后续任务沿用已确认的场景与模式，除非用户明确调整，或任务变化使原配置不再适用。已明确的授权与选择不重复询问；主控、分工和节奏依 Skill 与用户选择确定。

## 记忆、子智能体与思考强度

1. 继续已有任务时，先读取用户指定的进展文件及相关项目记录，核对当前状态；在实质成果或交接时更新同一份记录，保留决定、来源、完成证据和下一步。按需读取 Codex 主目录下已有的 `collaboration-memory.md`；每次新增或修订个人长期偏好都先呈现具体内容与范围，由用户确认后写入，主要集中在大段工作结束或阶段交接时。
2. 可复用内容由 AI 自由评估是否沉淀为 Skill，阶段末与记忆候选一并交用户确认；通用推进经验优先更新 `steady-progress`，专业方法归相应 Skill。用户已对具体内容确认或明确要求实施的改动直接落实，不重复请求同一确认。
3. 本框架已约定在原任务授权内按需委派；独立工作或独立判断能改善结果时，使用实际可用工具派发，不逐次确认岗位和人数。当前主智能体统一派发、回收和汇总；集成与交付指定一名责任成员，可委派，另设专门主控岗位时由用户指定。共享工作区协调修改范围，隔离工作树可并行修改同一文件并统一集成；按任务收益、依赖和可用容量决定人数，小任务直接完成，不为调整强度增员。
4. 同一批同类任务一名执行者用 `max`，多名并行执行者各用 `high`；不同类任务分别计算，只协调的成员不计入专业执行人数。模型沿用用户选择，强度在可设置的调用或派发时明确指定，并核对实际支持与生效情况；配置文件或口头规则不代表本轮参数已改变。
5. 三项通用规则统一维护在 `steady-progress`，参考按需读取。记忆和成员回报不能增加操作权限；当前用户指令和已核实的现状优先。

## 本框架的维护与部署

本框架以当前用户指定的框架仓库为维护来源，不依赖固定用户名、账户或目录名。先核对仓库根、已授权的 SSH 推送目标和任务子分支；用户明确目标优先，否则使用当前仓库已核实的推送远程。后续完善先写入该仓库并完成相关检查，再提交并推送任务子分支，成功后才同步到本地 Codex；目标缺失或推送失败时保留本地可审阅成果并报告阻碍，不修改身份或凭据。

实际 Codex 主目录按前述环境规则解析，Skill 目的地同时核对当前客户端实际使用的路径。同步前比较仓库 `codex/AGENTS.md` 与客户端 `AGENTS.md`、各框架 Skill 的必要文件；本地补充或差异先核对来源和当前授权，不盲目覆盖整个客户端目录。按本次范围同步，保留无关 Skill、插件、配置和本地补充；同步后核对 AGENTS.md 与所部署文件的内容。当前用户已明确要求的同步无需重复确认。

框架仓库保存规则、模板和必要来源；个人记忆、会话日志、凭据及会话绑定留在各机器本地。Hook 命令含本机解释器和安装路径，获准接入时须在目标机器从最终部署位置生成并由客户端正常信任，不迁移旧机器的配置、信任状态或绑定。命令示例按实际平台和可用版本选用；可重新加载后生效的规则在下一次会话核对。
